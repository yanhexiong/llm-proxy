# 通用 HTTP 透传验收

日期：2026-09-19。版本：0.1.3。公网：`https://converter.yahenix.top`。

三种已知生成端点继续执行原有协议转换；其他路径自动转发。接口路径没有模型列表、token 用量或供应商白名单，也没有 DeepSeek 模型查询专用重写。后续增加新的普通 HTTP 接口不需要在网关注册路由。

## 运行时验证

Workers 运行时测试 62/62，部署脚本测试 14/14，类型检查和构建通过。新增测试覆盖：

- 九种协议方向的模型列表，原始 JSON、分页及重复查询参数。
- 未知 `token_usage`、`api/usage/token` 路径的 POST、DELETE、HEAD 和二进制请求／响应。
- 应用自定义头、原有认证头、目标协议认证头补齐、Cookie 与连接专用头隔离。
- 原样保留上游错误、Retry-After、配额头及不自动跟随重定向。
- 别名更新、撤销、目标／协议篡改、缺失 API Key 和编码路径越界拒绝。
- 已知生成端点仍只接受 POST，不能意外进入通用透传分支。

## 公网和 SDK 验证

使用 `test_env` 中已有凭据，以 HTTP 请求及官方 OpenAI／Anthropic SDK 检查现有九种协议方向的链接；没有重新生成授权链接，也没有调用模型生成。额外访问供应商余额查询接口验证通用路由，报告不记录余额数值。

| 检查 | 结果 |
| --- | --- |
| 标准基址的 `/models`、`/v1/models` 查询 | 12/12 返回真实模型列表 |
| 官方 SDK 的模型列表查询 | 6/6 返回真实模型列表 |
| 标准基址下另一种 `/user/balance` 接口 | 6/6 成功，响应结构保留 |
| 上游兼容子路径未开放模型列表 | 9/9 保留上游实际 404（含 SDK） |
| 合计 | 33/33 符合预期 |

33 项通过不代表所有基址都提供模型接口。此次 DeepSeek 标准基址支持模型列表，其 Messages 兼容子路径不支持；通用透传保留后者的 404，不猜测根目录。其他供应商需要在所填基址下实际提供对应 API。

复现命令：`pnpm run test:live models`。本地详细报告保存在被 Git 忽略的 `test-results/live-models.json`，不会包含 API Key、Cookie、完整授权链接或余额金额。

## 工具侧配置边界

工具应在代理 Base URL 后追加接口路径，保留签名链接前缀。网关只移除自身首个虚拟 `/v1` 挂载段，保留供应商 Base URL 的路径前缀；不跨域寻找接口，也不把供应商子路径自动替换为根目录。若工具的用量接口位于另一个基址，可以为那个基址生成一条独立链接，再填写到工具的用量查询 Base URL。

本次未运行 CC Switch 桌面程序本身；针对其用量查询采用的方法、路径、Header 和原始请求体形式完成了运行时验证。[CC Switch 用量查询说明](https://github.com/farion1231/cc-switch/blob/main/docs/user-manual/zh/2-providers/2.5-usage-query.md)
